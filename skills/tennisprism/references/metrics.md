# 逐拍数据与动作对比

默认任务是一段视频的训练复盘。Agent 查看真实画面、标注能确认的动作；脚本校验引用并计算样本统计。当前没有整场自动找拍或球轨迹引擎，长片的统计范围始终是已查看、已记录的样本。

## 能从当前证据得到什么

| 数据 | 需要的画面或计算 | 输出口径 |
| --- | --- | --- |
| 正手、反手、发球等类型 | 能辨认人物、球拍侧和动作过程 | 已记录样本的类别与数量 |
| 触球高度 | 能确认球拍与球在触球阶段的位置，并看到身体参照 | 低于髋部、髋到肩之间、高于肩部；边界或透视不清时 unknown，不换算厘米 |
| 来球深浅、出球深浅 | 分别看到相应落地过程与球场区域 | 来球和出球分开记录；不可见填 unknown |
| 分腿垫步 | 足够连续、清晰的脚步时序 | 观察到、足够证据下未观察到、未知 |
| 准备至触球、触球至回位间隔 | 两个事件分别有真实帧，触球可见 | 已标注事件之间的秒数及采样限制 |
| 相对手腕高度、站距、肘角 | 当前视频和目标的真实、复核过的二维姿态 | 投影指标，按下文定义计算 |

深浅使用统一的球场区域：short 为发球线以内，mid 为发球线至底线区间靠网的一半，deep 为该区间靠底线的一半。看不清球场参照、落地或出界情况时填 unknown，不靠挥拍幅度推断。它是画面中的粗分类，不是落点坐标或界内判罚。接到深球与把球打深是两个不同变量。

`split_step=not_observed` 仅用于完整可见的相关脚步过程确实未见分腿垫步；脚被挡住、采样错过或只有单帧时必须用 unknown。`contact_basis=estimated` 表示从前后过程推断的触球，不计入已确认触球高度与时间指标的汇总；可保留记录供回看。

`contact_basis=visible` 指触球阶段有球与拍面位置相合、并有相邻帧的来球与击后过程支持；所引帧是可见阶段的代表帧，不保证捕获真正碰撞的瞬间。只有挥拍动作、模糊拖影或二维偶然重叠时用 estimated。备注说明模糊、遮挡和时间不确定性，不把时间戳小数位当测量精度。

只要求数据的任务完成记录与计算即可，不需要为了使用数据脚本新增评级或完整报告。

## 执行与保存

1. 查看概览和时序图，选择有意义的击球样本。必要时在提交报告前 `sample` 补足前后过程；新任务必须使用新的 manifest，不能混用旧任务帧号。普通长片复盘尽量覆盖前、中、后和主要击球类型，实际覆盖不足时在报告集中说明。
2. 读取 `../scripts/tennis_runtime/shot_schema.json`，按契约生成逐拍观察 JSON。`evidence_id`、`target` 使用当前任务的实际值。每条 evidence 的帧号、解码时间来自 manifest；每个非空阶段帧必须包含在该拍 evidence 中。`note` 写可见过程、遮挡或判断理由。左右手使用球员的身体左右，不使用画面左右。
3. 在 `submit` 前运行 `python <skill>/scripts/coach.py shots --workspace <workspace> --run <run-id> --observations <observations.json>`。`inspect` 提供契约和已保存数据的路径；脚本校验后保留版本化的观察与统计文件。再次提交观察会创建新版本，历史保留；命令失败要修正实际原因，不手改统计或覆盖历史。
4. 环境可用时按 [H5 与姿态](h5.md) 生成并复核当前任务姿态。长片可按逐拍证据窗口推理，姿态数据不会把采样扩充成全场覆盖。依赖不可用或节点不可信时继续交付分类数据，不编造骨架或计算值。
5. 用实际输出支持报告中的观察与训练建议，执行 `submit`，再生成 H5。H5 从当前观察版本与可用的已复核姿态重新计算统计；聊天中若引用姿态数值，核对最终生成的数据，避免引用加姿态之前的旧结果。逐拍数据继续由独立文件承载；主报告使用当前报告契约，不追加任意测量字段。没有可靠击球样本时可以提交空记录，报告说明本次未获得可用逐拍数据。

默认短时序请求 8 fps；错过快速触球时，可在 `prepare` 或 `sample` 指定 `--detail-fps 15` 或 `--detail-fps 30`，并用 `--focus-times` 指向实际找到的动作。比如 `coach.py sample --workspace <workspace> --run <当前任务号> --focus-times <触球附近秒数> --detail-fps 30`。最多四组短时序，各保持约 0.875 秒窗口，30 fps 时最多 27 张请求帧，视频端点附近可能更短；请求频率不超过源片帧率。实际帧数与时间以新 manifest 为准，不把加密采样说成精确触球识别或整段高帧率分析。

采样中的一次击球只记录一次，不能把准备、触球、随挥算成三拍。触球时间无法定位时仍可记录确实发生的动作类型，其触球阶段为空；不得为填满数据猜一个精确时间。准备帧对应可见准备开始，回位帧对应完成本拍后重新进入可继续应对来球的准备状态；事件不完整则留空。间隔不是从对手击球开始的反应时间，也不等于步速。

## 二维姿态指标

脚本只在触球可见、已复核姿态匹配当前预览和人物、对应姿态帧距离触球时间不超过 0.05 秒时计算。相关节点 visibility 和 presence 均需达到 0.65，长度分母必须有效；缺失结果为 null，不能当作 0。姿态置信阈值不代表测量正确的概率，采样间隔也不代表测量精度。

- `wrist_height_torso_2d`：画面髋中点到击球手腕的竖直高度，除以画面髋中点到肩中点的竖直高度。0 为髋中点高度，1 为肩中点高度；它不是球的高度、身高比例或离地高度。
- `stance_shoulder_ratio_2d`：画面中的双踝距离除以双肩距离。受相机角度、身体转动和遮挡影响，不直接对应实际站距。
- `elbow_angle_2d_deg`：同侧肩—肘—腕在画面平面的内角。只描述投影，不当成三维关节角，更不套用统一“应该伸到多少度”的阈值。

这些指标用于回到画面提出可验证的问题。手腕高度不能代替拍头轨迹或上旋；髋中点不是人体重心；姿态不能测量蹬地力量、动力链效率或伤病风险。现阶段不提供真实击球高度厘米值、三维髋肩分离角或自动 ACE 计数。

## 统计如何进入训练建议

引用脚本输出的样本数和有效分母。例如可以说“可确认触球高度的样本中，高于肩部占……”，不能改成“全场高点击球率”。未知与估计项单列，分母不能随需要变换。数值零只用于真实可计算的零；没有样本时不显示为 0%。整体中位数可能混合正手、反手和不同来球，只作样本描述；训练对比先筛选同类动作，不用整体数值判断技术好坏。

看高球多、回位时间较长或投影角变化，不自动推出技术错误。结合来球、站位和结果提出解释，再给具体试练及验证标准。一个问题只有一次清晰证据时可以给潜在问题试练，但不声称是重复习惯。脚本保证相同观察输入与同版计算规则得到相同统计；它不能保证 Agent 每次标注、训练判断或 NTRP 估计完全一致。

## 独立的动作对比模式

用户明确要求对比时，先在同一视频里选择两组：前后时段，或同一类动作。按击球类型、来球深浅、触球高度以及画面可确认的移动情境尽量匹配，说明仍不同的条件。用户说“正手深球”时，依据上下文区分“正手处理深来球”和“正手打出深球”；如果这决定比较对象而上下文不足，再简短确认。

每组都保留原时间点、样本数量、有效数和未知项。用真实触球事件对齐准备—触球—回位过程；估计触球单列。可比较分布和重复出现的问题，不从两个挑选出的好坏动作推断总体提升，也不把视频后半段的变化直接归因于疲劳。来球或拍摄条件不匹配时，给出条件差异或补拍建议。

当前支持依据逐拍记录开展教练对比分析；没有自动动作聚类、自动证明进步或双播放器同步对比功能。跨视频比较也需分别绑定各自证据和拍摄条件，不把原始二维坐标直接相减。
