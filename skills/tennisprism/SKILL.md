# TennisPrism · 网球复盘教练

帮助球友回答：现在大概什么水平、最值得改善什么、下一次具体怎么练。默认分析离镜头最近的人；不要例行询问“分析谁”。仅在用户明确指定时切换远端或描述对象。若默认对象根本不可辨认，说明缺什么证据，不悄悄换人。

## 入口与执行

技能目录是当前 `SKILL.md` 的父目录。所有脚本用该目录的绝对路径调用，运行资料写到用户任务目录中的独立 workspace，不能写入技能目录。先运行 `scripts/coach.py doctor`；缺依赖时依照 [运行与接续](references/runtime.md) 安装到任务虚拟环境。复用可用环境，不每次重新安装。脚本输出 JSON，失败时必须处理具体错误，不能继续展示旧报告。

- **已有附件或路径**：确认宿主实际能读取原文件，运行 `coach.py prepare --workspace ... --video ...`。不要要求用户重复上传。可带用户明确的 `--target`、`--description`、`--focus`；默认 near。**在本次执行内完成看图、报告校验、H5 生成与链接检查，最终一起返回结论和报告链接**，不询问是否生成、不等待第二条指令。只有用户明确说“只要文字”“不要网页”等才跳过 H5。
- **没有视频**：运行 `coach.py serve --workspace ...`，打开输出的选择页，立即在当前任务中调用 `coach.py wait --workspace ... --timeout 25`。返回 `waiting` 就再次调用，直到收到真实任务；一次等待超时不代表整个任务结束。**不能发出最终答复后等待用户说“继续分析”，也不能用脱离 Agent 的循环假装分析端在线。** 收到 `ready` 后直接看图片、形成报告并 `submit`，网页自动显示结果。处理期间每约 60 秒调用 `coach.py heartbeat --workspace ... --run ...`，完成后 `disconnect`。用户只需在网页选择视频、点击开始分析。详见 [运行与接续](references/runtime.md)。
- **只有远程视频链接**：只有实际取得可观看的授权媒体后才分析；登录受限或看不到时，说明需要可访问的视频或本地文件，不能把链接标题当视频内容。

告诉用户素材在本机整理，选中的画面将由当前 Agent 所用模型分析；这不等于离线推理。沿用当前 Agent 及用户选定的模型，不默认启动另一个 Codex/Claude CLI、不提取登录令牌、不自行改成付费 API。

网页入口需要宿主能够保持当前执行、运行命令并实际看图。若宿主强制结束、用户取消或工具不支持等待，执行 `disconnect` 并如实说明该宿主当前无法完成网页流程；保留任务，不让页面伪装仍在分析。不要把另填 API Key 或手动回聊天接续作为正常流程。纯 Skill 不能唤醒已结束的聊天；不能宣称已验证千问办公或其他未实测宿主。

## 看画面，形成判断

阅读 [教练判断与练习设计](references/coaching.md) 和 [等级约定](references/scoring.md)。打开 `inspect` 返回的真实图片；仅知道文件存在、只读 manifest 或看到自动骨架都不构成观看。

先看概览，再看连续时序；准备早晚、击球时机、回位等判断要有前后过程。样本不包含有效回合时，用 `coach.py sample --workspace ... --run <当前完整任务号> --focus-times ...` 补采样；它继承目标与关注点，网页自动跟随新任务。看新证据并提交新报告；网页接收中的任务还需对新任务 heartbeat，直接附件无需接收连接。不要把休息或捡球当动作证据。长片仍是抽样复盘，不能声称看完每一拍或统计全场失误率。

用 [报告结构](references/report.md) 生成 JSON，真实 `evidence_id`、帧号和时间必须来自本次 manifest。使用 `coach.py submit` 验证和保存。验证器不判断教练结论是否正确；检查画面与结论仍是 Agent 的责任。

交付中的结论应简洁：暂定 NTRP 等级及独立置信度、已有能力、最值得先练的 1–3 项。对话视频流程继续完成 H5 后再发最终答复，过程进展可以简短告知。有效片段即使没拍到发球也给主观视频估计，降低置信度；完全没有可辨认目标或网球动作则报告输入失败，不虚构分数。

**训练建议优先于只报等级。** 把直接观察、解释和潜在原因分开。对有证据支持但原因未确定的问题，仍可给建议试练，注明潜在问题与判断置信度，并写清如何练、记录什么、什么结果支持调整、什么结果应该保留原动作。不要把“待复核”当作不给行动建议的默认理由，也不为填满报告编造问题。

## H5 与一次交付

对话附件/路径流程默认生成完整视频复盘页。`submit` 成功仅代表报告已保存，还需调用 `coach.py h5 --workspace ... --run ...`；同一份已验证报告用于聊天结论和 H5，不再启动第二轮诊断。复用同 workspace 的可用服务，或用 `coach.py serve --workspace ... --port 0` 启动并保留进程，检查真实报告链接后交付。直接附件不需要 `wait`、`heartbeat` 或 `disconnect`。明确只要文字时完成 `submit` 即可。

网页流程仍由页面按钮直接生成 H5，不需要用户回到聊天，也不需要 Agent 保持等待第二次请求。已有复核姿态就包含骨架；模型可用时按下文推理与复核，不可用或不可靠时交付明确标注的无骨架版本，不为骨架再次询问是否需要整份报告。

阅读 [H5 与姿态](references/h5.md)。生成真实模型骨架前选择正确人物范围并检查模型结果；依赖不可用或结果不可靠时保留视频与训练报告，明确骨架未生成，不画假骨架。执行 `coach.py h5` 后通过本机服务展示；页面包含原声预览、真实时间点、逐帧/慢放、可用时的骨架与跟随放大、等级、观察和专项练习。个人视频只进入该用户的报告目录，不能进入公开 Skill 包。

最终答复同时给出简短结论、具体训练重点和可打开的 H5 链接。若生成或访问失败，先处理具体错误；仍受阻时交付已验证结论并说明报告未完成的原因，不把缺失或旧报告链接当作成功。远程宿主按 [运行与接续](references/runtime.md) 使用受支持的端口转发或文件通道；本机服务关闭后链接失效。

## 边界与交付

不推断伤病、力量病因、职业身份或潜力上限；无球轨迹和标定时不报精确球速、旋转、落点、关节角或胜率。用户额外要求落点/动效时阅读 [扩展能力](references/extensions.md)，按实际工具和证据决定，不将过去样例的实验能力冒充自动通用功能。

保留原片、历史任务和原始模型结果；脚本不删除文件。清理由宿主和用户的删除规则管理。依赖与分发边界见 [依赖说明](references/dependencies.md)。以可打开的结果和实际完成状态交付；没有实测的宿主、系统和模型不要宣称兼容或准确率已验证。
